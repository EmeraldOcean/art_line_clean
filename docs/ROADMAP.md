상태: ⬜ 대기 · 🔄 진행 · ✅ 완료 · ⏸ 보류

## 공통 완료 조건 (DoD)
1. `uv run pytest` 전부 통과 (실행 결과 첨부)
2. 해당 기능의 합성 케이스 비교 시트(입력 | 출력 | 차이) 생성
3. 비생성 검사·원본 불변 검사 통과
4. ROADMAP 상태 갱신 + DECISIONS에 새 결정 기록 + 미해결 문제 보고 + 커밋 메시지 제안
5. 위 중 하나라도 확인하지 못했으면 "완료"가 아니라 "부분 완료"로 보고

## M2 기록 (2026-11-01)
- 추가: `merge.py`(덧그림 판정·중간선 병합·판정 기록), `render.py`(임시 렌더러, 합성 이미지와 공유), `compare.merge_overlay`, CLI `--merge`, 합성 케이스 `shallow_cross`·`touch_and_diverge`·`base_paths()`
- 방식: 엣지 점마다 "가까이(≤2.5w) 나란한(≤20°, 구조 텐서 방향) 다른 엣지"가 있는지 보고, 60% 이상이면 겹친 엣지 → 묶어서 그룹 안에서만 닫힘 → 단일 경로면 중간선으로 다시 그림. 비생성 위반이면 되돌림
- 검증됨: pytest 81개 통과. 덧그림이 아닌 합성 12개는 `--merge`에서도 픽셀 단위 동일. overdraw2_gap3은 선 하나로 병합(중간선 오차 ≤ 1.29px, 양 끝 10% 제외). 모든 케이스 비생성 위반 0
- 실제 러프: 26개 그룹 병합, 분기점 300→174, 고리 174→97, 비생성 위반 0
- **미해결 (실제 러프 품질)**:
  1. 병합이 조각조각 일어남: 긴 덧그림 중 기준을 넘는 구간만 바뀌어 한 윤곽 안에 1중선·2중선 구간이 번갈아 나타나고, 경계에 작은 끊김이 생김
  2. 다시 그린 구간이 주변보다 진하고 매끈해 눈에 띔 (연필 질감 없음)
  3. 머리 윗부분처럼 서로 다른 선이 얕게 만나는 곳을 병합한 것으로 보임 (사용자 확인 필요)
- D-10(병합 방식·파라미터)은 위 문제의 방향을 정한 뒤 기록

### M2 보완: 획 단위 판정 (2026-11-01)
- 추가: `strokes.py`(분기점에서 가장 곧게 이어지는 엣지끼리 잇는 획 엮기, ≤35°)
- 판정을 획 단위로 변경: 짧은 쪽 획의 겹침 ≥ `min_cover`일 때만 병합. 일부만 덮인 긴 획은 겹친 구간만 지우고 중간선 끝을 그 획 위로 옮겨 붙임(끊김 없음). 농도는 이어지는 원래 획에 맞춤
- 합성: `partial_overdraw`(가운데만 덧그림 → 끊김 없는 선 하나), `shallow_merge`(얕게 만나는 다른 선 → 그대로) 추가. pytest 90개 통과
- 실제 러프 결과는 `min_cover`에 크게 좌우됨:

| min_cover | 병합 | 분기점 | 고리 | 관찰 |
|---|---|---|---|---|
| (1차, 엣지 단위) | 26 | 174 | 97 | 조각난 병합, 끊김 |
| 0.8 (현재 기본) | 1 | 287 | 166 | 안전하지만 효과 거의 없음 |
| 0.5 | 10 | 188 | 105 | 어깨 2중선은 깔끔하게 병합. 눈 윗선(쌍꺼풀일 수 있음)도 병합, 머리 윗부분은 옅어지고 교차점 주변에 부스러기가 남음 |

- 합성 `shallow_merge`(서로 다른 선)의 겹침이 정확히 0.50이다. 그래서 0.5로 낮추면 이 케이스도 합쳐진다. 기하만으로는 0.8과 0.5 사이에서 "덧그림"과 "다른 선"이 갈리지 않는다
- 결정: 반자동 (D-10)

### M2 마무리: 반자동 병합 (2026-11-01)
- `--merge`: 확실한 후보(겹침 ≥ 0.8)만 자동 병합하고, 모든 후보에 번호를 붙여 오버레이(2배 크기)와 기록 CSV(`candidate`, `auto_ok` 열)에 남김
- `--merge-ids 3,7`: 고른 후보만 병합. 잘못된 번호면 아무것도 쓰지 않고 종료 코드 2
- 끝 연결: 중간선의 각 끝을 이어지는 부분이 가장 긴 획 하나에만 옮겨 붙임 (두 획 모두 일부만 덮인 경우 대응)
- 합성 `double_partial`(두 획이 엇갈려 가운데만 겹침): 자동으로는 그대로, 고르면 끊김 없는 한 줄
- pytest 101개 통과. 실제 러프: 후보 18개, 자동 병합 1개(9번), 비생성 위반 0
- 사용자 검증: 실제 러프에서 후보 16(어깨 2중선)·9(왼쪽 턱선)를 골라 병합, 비생성 위반 0. 사용자가 결과를 받아들여 M2 완료
- 이후로 넘긴 문제:
  - 턱선(9번) 아래쪽 이음매가 살짝 꺾이고 위쪽 끝에 작은 점이 남음 → 끝 연결 길이 조정 (M6 파라미터 정리)
  - 합친 선이 원래 가닥보다 가늘고 매끈함 (연필 질감 없음) → M5
  - 얼굴 3중 윤곽(5·11번 등)은 대표선이 한 줄로 정리되지 않아 병합 불가 → 별도 검토
  - 짧은 가닥의 꼬리가 가지처럼 남음 (16번 왼쪽 시작점) → 설계대로지만 M6에서 다시 봄

## M3 기록 (2026-11-01)
- 추가: `junction.py`(X 판정·교차점 합치기, 위상 요약·비교), `strokes.build_strokes(forced_pairs=)`, `compare.topology_overlay`, CLI 위상 검사·`--topology-overlay`, 합성 `cross_30`·`two_t_close`·`y_then_cross`
- 병합(`merge.py`)도 교차 정리한 그래프로 획을 엮는다
- 검증됨: pytest 140개 통과
  - shallow_cross(12°)·cross_30이 차수 4 교차점 하나 + 곧은 획 2개가 됨
  - two_t_close(어긋난 T 두 개)는 T 두 개 유지, 사다리 가로대는 X로 합치지 않음
  - 합성 전 케이스 `--merge` 후 처리 영역 밖 위상 변화 없음
  - 출력 이미지: 항등 처리는 그대로. 실제 러프 `--merge-ids 16,9` 결과가 M2 결과와 픽셀 단위 동일
- 실제 러프: 교차 7곳을 합침. 목–어깨 X(977, 449)가 교차점 하나로 잡히고 획이 곧게 통과함을 오버레이로 확인. 나머지 6곳은 덧그림 가닥끼리 엇갈린 곳
- 실제 러프 위상 요약(항등): X 75, T/Y 204, 끝점 88, 기타 14
- 미해결:
  - 위상 수치 대부분이 덧그림 가닥이 서로 닿거나 엇갈린 곳이다 (의미 있는 교차는 목–어깨 정도). 덧그림을 더 병합해야 수치가 그림의 실제 구조에 가까워진다
  - 후보 번호가 바뀜: 교차 정리로 획 엮기가 달라져 실제 러프 후보가 18 → 17개, 3~6번과 17번(목–어깨, 옛 17·18번이 하나로)의 번호·범위가 바뀜. 9·16번은 같음
  - 위상 검사는 처리로 바뀐 픽셀 근처(6px)를 빼고 본다. 처리 영역 안의 교차가 유지됐는지는 합성 테스트로만 확인한다. M4처럼 넓게 바뀌는 처리에는 별도 기준이 필요하다

## M4 기록 (2026-11-01)
- 추가: `smooth.py`(모서리 찾기, 계단 제거 중심선, 수축 없는 평활 2G−G∘G, 가로 방향 변위만, 최대 1px·0.4px 미만 무시, 곁에 다른 획이 있는 점은 고정, 원본 픽셀 역방향 변형, 위상이 바뀐 곳 근처 획은 되돌림), CLI `--smooth`·평활 전용 엄격 위상 검사, `junction.topology_changes`
- 검증됨: pytest 175개 통과
  - 깨끗한 합성(직선·곡선·가늘어지는 선·희미한 선·모서리·30° 교차)은 픽셀 단위 그대로
  - 합성 전 케이스: 평활 전후 위상 변화 0 (제외 영역 없이), 최대 이동 ≤ 1px, 비생성 위반 0
  - wobbly_curve: 정답 곡선과의 최대 이탈 1.71 → 1.46px, 떨림 지표 0.175 → 0.157 (−10%). **평균 이탈은 0.60 → 0.60으로 그대로, 계획한 30% 감소 목표에는 못 미침**
- 실제 러프 (`--smooth`): 옮긴 픽셀 758, 최대 0.86px, 떨림 지표 0.174 → 0.170px (−2%), 비생성 위반 0, 평활 위상 검사 변화 없음
  - 원인: 이 그림의 중심선 떨림 자체가 작고(평균 0.17px), 떨림처럼 보이는 거친 느낌은 대부분 연필 가장자리 질감과 덧그림 가닥이다. 덧그림 가닥은 서로 닿거나 떨어지지 않도록 움직이지 않게 했다
  - 1px 상한은 효과를 막고 있지 않다(2px로 올려도 결과 동일). 0.4px 기준을 0.2px로 낮추면 떨림 지표가 조금 더 줄지만(0.167), 깨끗한 직선·곡선까지 흐려진다
- 미해결: 효과가 작음. 거친 인상을 줄이려면 M5(가장자리·굵기 정리)나 덧그림 병합 확대가 더 직접적이다
- 사용자가 효과가 작은 현재 결과를 받아들여 M4 종료 (2026-11-01)

## M5 기록 (2026-11-01)
- 추가: `render.render_clean`(획별 굵기·농도 측정 → 매끈한 가장자리로 다시 그리기), `junction.connectivity_changes`, CLI `--render`(병합 → 평활 → 다시 그리기 순), 합성 `pencil_texture`
- 방식: 중심선 σ=1.5px, 굵기 = 2r−1을 이동 중앙값으로 튀는 값 제거 후 상한(획·전체 중앙값의 1.5배), 획을 따라 σ=2w로 평활하고 번짐 0.5px 뺌. 농도는 띠(굵기/2+1.5px) 단위로 원본 알파 합 ÷ 다시 그린 덮임 합(잉크 총량 맞춤). 겹치는 획은 최댓값. 획이 없는 잉크 덩어리는 원본 그대로. 원본 잉크+2px 밖은 잘라 냄. 다시 그린 뒤 잉크 연결(붙음·끊김·사라짐)이 바뀐 곳 근처 획은 원본 유지
- 검증됨: pytest 186개 통과
  - line·curve: 굵기 오차 ≤ 0.5px, 중심선 이탈 ≤ 0.5px, 잉크 총량 0.95~0.97
  - tapered: 가운데 굵기 유지, 양 끝이 가늚
  - faint_thin: 지워지지 않음, 중심 농도 84 → 69 (−18%)

  - 골격 위상(X/T/Y) 일치를 기준으로 쓰면 가장자리만 바뀌어도 어긋나 실제 러프 획 189개 중 178개가 원본으로 되돌아감 → 기준을 잉크 연결로 바꿈 (골격 위상은 다시 그리기에서 참고만)
  - 붓 좌표와 픽셀 인덱스가 0.5px 어긋나 다시 그린 선이 대각선으로 밀림 → 수정. M2 병합선 렌더링에도 같은 어긋남이 있어 함께 수정함 (병합 결과가 M2 때와 조금 달라짐)
- 미해결:
  - 병합하지 않은 덧그림(오른쪽 얼굴 윤곽, 머리 옆, 목)은 깔끔한 가는 선 여러 가닥이 군데군데 닿아 작은 고리가 이어진 사슬처럼 보인다
  - 잉크 총량을 맞추다 보니 선이 원본보다 가늘고 진해 보인다
  - 골격 위상 수치는 다시 그리기 전후로 크게 달라진다 (가장자리가 바뀌므로). 판정에는 잉크 연결만 쓴다
