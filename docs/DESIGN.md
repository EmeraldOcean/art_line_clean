# 설계 및 검증

## 1. 처리 구조
```
이미지 → [마스크] → [선 그래프 추출] → [그래프 정리: 병합 / 교차 해소 / 평활화] → [렌더링] → 이미지
```
- 각 단계는 순수 함수. 입력을 변경하지 않고 새 객체를 반환한다.
- 단계마다 중간 결과를 시각화할 수 있다.
- 그래프 추출 방법은 교체 가능(세선화, 중심축 등). 어떤 것을 쓸지는 DECISIONS에 기록한다.

## 2. 중간 표현: 선 그래프 (Stroke Graph)
- 노드: 끝점, 분기점, 교차점 (좌표, 종류)
- 엣지: 폴리라인 좌표 배열 + 점별 반지름(굵기/2) + 점별 알파
- 구조 정리(A~C)는 그래프만 다루고, 렌더링(D)은 그래프 → 이미지만 다룬다.

## 4. 알고리즘 후보와 현재 판단
**그래프 추출은 확정(D-8)**: `skeletonize` + α ≥ 16, 블러·히스테리시스 없음, 잔가지 가지치기.
덧그림 병합은 M2에서 그래프 단계로 구현한다(방식 세부는 M2 계획에서 확정).
근거: [experiments/M1_REPORT.md](experiments/M1_REPORT.md). 아래 4.1·4.2는 M1 이전의 검토 기록이다.

### 4.1 세선화에 대한 검토
세선화는 두꺼운 **단일 선의 중심선**을 찾는 데는 좋지만, 덧그은 선 병합(F-A)의 해법은 아니다.

| 상황 | 세선화 결과 | 문제 |
|---|---|---|
| 덧그은 두 선 사이에 틈이 있음 | 스켈레톤 2개 | 병합 안 됨 (세선화는 연결성을 보존) |
| 두 선이 부분적으로 겹침(작은 구멍) | 스켈레톤에 고리(loop) | 가짜 닫힌 경로 |
| 두 선이 완전히 겹쳐 한 덩어리 | 합집합 중심 1개 | 이 경우만 M(t)와 비슷하게 해결 |
| 굵은 선 끝, 가장자리 요철 | 잔가지(spur) | 짧은 진짜 선과 구분 어려움 |
| X 교차 | Y 두 개 + 짧은 다리 | 위상 왜곡 |
| 날카로운 모서리 | 안쪽으로 둥글게 당겨짐 | 형태 변형 |
| 희미한 선 | 임계값에 따라 끊김 | 연결 관계 손실 |

중간 경로 M(t) = (A(t)+B(t))/2 는 대응점 A(t)↔B(t)를 안다는 전제가 필요하다.
실제 난제는 평균이 아니라 **대응 찾기**(어느 구간끼리 짝인지, 길이가 다를 때 정렬)이며,
3개 이상 덧그림에는 중앙값/가중 평균이 더 견고하다.

### 4.2 대안 비교
| 접근 | 장점 | 단점 | 판단 |
|---|---|---|---|
| a. 이진화 + 세선화 + 그래프화 | 단순, 끝점/분기점 추출 쉬움 | 4.1의 문제, 굵기 소실 | 1차 실험 기준선 |
| b. 거리변환 기반 중심축(medial axis) | 중심선 + 반지름(굵기) 동시 획득 | 잔가지가 더 많음 | a와 함께 비교 |
| c. 방향장(structure tensor) 기반 그룹화 | 평행 덧그림/교차를 방향으로 구분 | 스케일 파라미터 민감 | A·C 보조 수단 후보 |
| d. 선 조각 쌍 매칭 + 정렬(DTW 등) + 평균 | M(t) 아이디어 일반화, 틈 있는 덧그림도 병합 | 짝 판정 규칙이 핵심 위험 | a/b 위의 병합 단계 후보 |
| e. 닫힘(closing) 후 세선화 | 구현 최단 | 별개 선까지 붙임 — 원칙 위반 위험 | 비권장(비교용) |
| f. 외곽선 벡터화(potrace류) | 매끈함 | 덧그림이 그대로 남음, 중심선 아님 | 부적합 |
| g. 소형 학습 모델(스케치 단순화 CNN 등) | 품질이 높을 수 있음 | 출력 픽셀 생성 → 비생성 원칙 충돌 가능, 설치·라이선스 부담 | 보류. 재검토 시 "원본 잉크 영역 밖 출력 금지" 제약 필수 |

## 5. 검증 전략
### 5.1 단위 테스트 (pytest)
- 합성 이미지는 코드로 생성한다(정답 기하를 알고 있음) → 기하 오차를 수치로 검사.
- 공통 불변 검사(모든 처리 기능에 적용):
  - 크기·모드 유지, 입력 배열/파일 불변(해시)
  - 비생성 검사: 출력 잉크 ⊆ 원본 잉크 팽창(d)
- 기능별 검사 예:
  - 평행 덧그림 → 엣지 1개 & 정답 중심선과의 최대 이탈 ≤ 1px
  - 별개 평행선(넓은 틈) → 엣지 2개 유지
  - X 교차 → 차수 4 교차점 1개
  - 떨림 곡선 → 곡률 노이즈 감소 & 정답 곡선 이탈 ≤ 허용치

### 5.2 합성 케이스 목록
단일 직선/곡선, 평행 덧그림(틈 0/1/3px, 2·3회), 별개 평행선(틈 넓음 — 병합되면 실패),
X 교차, T 접합, Y 분기, 짧은 선이 긴 선에 붙음, 떨림 곡선, 날카로운 모서리,
가는 희미한 선, 끝이 가늘어지는 선, 안티앨리어싱 가장자리.

### 5.3 시각 검증
- 비교 시트: 입력 | 출력 | 차이(추가=빨강, 제거=파랑) | (선택) 그래프 오버레이. 투명 배경은 체커보드.
- 합성 케이스 전체 + `samples/input/`의 실제 러프에 대해 생성, `output/`에 저장.
- 실제 러프는 정답이 없으므로 시각 검증 + 비생성 검사만 자동화한다.

### 5.4 원본 보호
- `.claude/settings.json`의 `Edit` 거부 규칙은 Claude의 파일 편집 도구만 막고 셸·스크립트 쓰기는 막지 못한다.
- 그래서 `io.py`에서 출력 경로가 입력 폴더 안이거나 기존 파일이면 거부하고, 테스트로 확인한다.
